# Аналитика монетизации в игре: SQL

Анализ поведения игроков и их трат на внутриигровую валюту: кто платит, сколько и почему конверсия отличается между сегментами.

## Что делал

- Считал долю платящих игроков и разбивал её по сегментам (расе персонажа) через `JOIN` и условные агрегаты (`COUNT(CASE WHEN ...)`)
- Строил полную статистику по транзакциям одним запросом: `MIN/MAX/AVG`, медиана через `PERCENTILE_CONT`, разброс через `STDDEV_POP` — сразу увидел, что среднее в разы больше медианы, а стандартное отклонение почти в 5 раз больше среднего. Это указало на то, что доход держится на небольшой доле игроков
- Нашёл и отфильтровал технический шум в данных: нулевые и околонулевые транзакции, которые искажали статистику
- Через оконную функцию `SUM(...) OVER()` посчитал долю каждого предмета в общих продажах, не прибегая к дополнительному подзапросу
- Собрал сводную таблицу по сегментам одним CTE с несколькими `LEFT JOIN`, сразу считая конверсию, средний чек и частоту покупок в одном запросе

## Ключевые находки

- Раса персонажа почти не влияет на **вероятность** стать платящим игроком (разброс между сегментами ~3%), но сильно влияет на **паттерн трат**: где-то высокая частота при низком чеке, где-то редкие крупные покупки
- Выявлены аномальные транзакции (единичные покупки свыше 200 000–400 000 у.е.) — отдельно зафиксированы как выбросы, требующие проверки на связь с акциями

## Стек

PostgreSQL: CTE, оконные функции, `PERCENTILE_CONT`, `STDDEV_POP`, множественные `JOIN`
