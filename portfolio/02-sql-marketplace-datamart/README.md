# Витрина данных маркетплейса + 4 ad hoc задачи: SQL

Спроектировал и построил витрину данных для маркетплейса с нуля из сырых таблиц заказов, платежей и отзывов, затем решил 4 бизнес-задачи на её основе.

## Что делал

- Собрал витрину `product_user_features` — по одной строке на пользователя с полным набором метрик (число заказов, средний чек, доля отмен, использование промокодов/рассрочки, LTV) через цепочку `CTE` с агрегацией на разных уровнях (сначала по заказу, потом по пользователю)
- Заметил и поправил скрытую проблему в данных: оценки пользователей приходили в двух разных шкалах (1–5 и 10–50) — обработал это условной нормализацией прямо в `CASE WHEN` при агрегации
- Решил 4 независимые аналитические задачи поверх готовой витрины:
  - **Сегментация** пользователей по количеству заказов с оконной функцией `SUM(...) OVER()` для расчёта долей
  - **Ранжирование** пользователей по среднему чеку с фильтрацией по числу заказов
  - **Гео-аналитика** по регионам — доля рассрочки, промокодов, отмен на пользователя
  - **Когортный анализ** по месяцу первого заказа с `EXTRACT` — отследил, как меняется LTV и время жизни клиента в зависимости от месяца привлечения

## Ключевые находки

- 96% пользователей делают только один заказ — но лишь малая часть из них пришла по промокоду, значит нашли альтернативу, а не просто "выгорели" после акции
- Среднее время жизни клиента заметно падает от начала года к концу (13 дней в январе → 2 дня в декабре) — сигнал на сезонность оттока

## Стек

PostgreSQL: многоуровневые CTE, оконные функции, вложенные подзапросы, работа с некорректными данными на уровне SQL (без выгрузки в Python)
