# Прогноз риска задержки доставки: классификация + кластеризация

Проверка гипотезы, что предварительная сегментация клиентов методами обучения без учителя может улучшить качество классификатора — с полной защитой от утечки данных между кластеризацией и финальной моделью.

## Что делал

- Разбивал данные на train/val/test через **`GroupShuffleSplit`** — по клиенту, а не по строке, чтобы заказы одного клиента не оказались одновременно в обучающей и тестовой выборке
- Провёл географический аудит через scatter-plot координат клиентов, нашёл и отфильтровал аномальные точки за пределами заданного диапазона долготы
- Впервые применил **K-Means кластеризацию** сразу по двум направлениям:
  - геокластеры по координатам клиента
  - RFM-кластеры (recency, total_orders, total_sales, return_rate, avg_discount) — с интерпретацией каждого кластера как бизнес-сегмента ("лояльные", "утерянные", "риск возвратов")
- Подбирал число кластеров методом локтя (WCSS) для обоих случаев
- Строго разделил кластеризацию и итоговую модель по времени: центроиды кластеров считались **только на train-клиентах**, а для val/test использовался `.predict()` уже обученных кластеров — это исключило утечку данных
- Впервые применил **t-SNE** для визуальной проверки, насколько хорошо разделяются полученные кластеры в 2D-проекции
- Добавил кластерные метки как новые признаки в финальную модель и сравнил, помогает ли это `LogisticRegression` и `CatBoost` по отдельности
- Объяснил финальную модель через **SHAP**

## Метрики

Финальная модель — **CatBoost** с гео- и RFM-кластерами как признаками:
- **ROC-AUC вырос с 0.758 (без кластеров) до 0.773** на валидации, **0.761** на тесте
- Линейная модель (`LogisticRegression`) от кластерных признаков выиграла существенно меньше (0.732 → 0.738) — нелинейная модель извлекла из сегментации больше пользы

## Стек

`KMeans`, `t-SNE`, `GroupShuffleSplit`, CatBoost, `SHAP`, `phik`
